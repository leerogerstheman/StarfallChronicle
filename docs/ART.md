# 美术系统 / Generated art

这个项目里的所有人物形象都是**代码生成的 SVG**，没有一张位图，没有一个外部素材。

```
src/art/            ← 纯函数：spec 进，SVG 字符串出
  svg.js            构造器（含 Catmull-Rom → 贝塞尔）
  palette.js        配色、明暗、对比度
  body.js           人体骨架与零件（头/躯干/四肢/手/脚）
  face.js           五官与四种表情
  hair.js           七种发型
  outfits.js        服装零件（外套/裙摆/袖子/靴子/手套/领子/腰带/披风/护肩）
  gear.js           武器与道具
  motifs.js         元素氛围（风/火/冰/雷/虚数/量子/孢子/余烬）
  human.js          按固定图层顺序组装人形
  creature.js       按固定图层顺序组装非人形
  specs/            13 个形象的"画什么"（角色 5 + 敌人 6 + NPC 2）
  index.js          入口：renderArt(kind, id, opts) + 清单

public/js/art.js    ← 客户端：清单、URL、预加载
```

---

## 一、为什么是生成而不是画好存起来

三个理由，按重要性排序：

1. **不用构建步骤。** 项目的承诺是"双击就能玩"。如果美术是文件，就要有一个
   生成/导出环节，就多了一个会不同步的东西。现在是：改 spec → 刷新 → 看到。
2. **不会失同步。** 角色的名字、称号、属性来自 `src/core/characters.js`。
   `specs/characters.js` 只写"画什么"，名字是运行时从数据文件读的。
   把"苍叶"改名，立绘上的名字跟着变，不可能对不上。
3. **可以测试。** 生成的东西能被断言。`test/art.js` 有 21 项检查，
   `tools/art-sheet.js` 会在无头浏览器里把每张图栅格化后读像素。

代价是首次请求要算一次几何。所以渲染结果按 `(kind, id, view, expression, phase, plain)`
缓存，gzip 结果也一起缓存。

## 二、共享骨架：为什么五个角色看起来像一套人

**所有人类形象画在同一副骨架上。** 比例、四肢粗细、肩宽、头身比写死在
`body.js` 的 `JOINTS` 里，角色 spec 只决定发型、服装、道具、配色、姿势和身高。

这是唯一能让五个形象像同一个世界观的办法：**难用眼睛判断的部分只决定一次**。
手肘在哪、胯比肩宽多少——这些数值化定死，不会每个角色重新争论一遍。

```
全身边界  0 0 460 960，地面 y = 906
头高 124px，全身 824px → 6.6 头身（介于写实 7.5 与 Q 版之间）
头心 (230, 144)，肩 y = 262，腰 y = 430，胯 y = 478
膝 y = 674，踝 y = 860
```

### 身高

`spec.scale` 把整个人形**以地面为锚点**缩放：

| 角色 | scale | 读起来 |
|---|---|---|
| 苍叶 | 0.95 | 最矮，年轻 |
| 御巫铃 | 0.97 | |
| 神代凛 | 1.00 | 基准 |
| 艾莉丝 | 1.01 | |
| 白鸦 | 1.03 | 最高 |

代价是：缩放锚在地面，所以越高的角色头发离画布顶越近。
`bustView(scale)` 因此是算出来的而不是常量——不然最矮的角色的头像会正好切在眼睛上。
`test/art.js` 里有两项专门守这个：所有几何必须在画布内，且顶部余量 ≥ 14 单位。

## 三、曲线：Catmull-Rom，不是手写贝塞尔

手写三次贝塞尔是矢量美术变成一团魔法数字的原因。这里所有有机形状
（头发、布料、四肢）都由**锚点列表**定义，`svg.js` 用 Catmull-Rom 插值成贝塞尔：

```js
smoothClosed([
  [230, 82], [196, 92], [180, 122], [178, 156],
  [188, 186], [208, 203], [230, 208], [252, 203],
  [272, 186], [282, 156], [280, 122], [264, 92],
], 0.92);
```

好处是"把刘海改尖一点"是改一个坐标，而不是重画四段控制点。
`tension` 参数控制松紧：`0.12` 接近直线（石头、甲壳），`0.9` 接近圆滑（皮肤、布料）。

四肢用 `limb(a, b, wa, wb, { bend, bulge })`：中心线是过 `a`、`bend`、`b` 的二次曲线，
沿采样点插值半宽并加上 `bulge * sin(πt)` 的鼓起。两侧轮廓来自同一次采样，
所以不可能出现"左边比右边粗"。

## 四、图层顺序就是设计本身

平面矢量人物"看起来不对"几乎总是图层放错了：领子在下巴上面、武器在手指前面、
头发盖住了它该盖住的脸。`human.js` 把顺序定死一次：

```
aura        背景光晕（径向渐变，很暗，不跟 UI 抢）
ground      接地阴影
cape        披风 / 外套后摆
hairBack    脑后发团（长发、丸子头）
neck        脖子（被下巴和领子压住）
legs        腿（皮肤）
boots       靴子 ← 必须在衣服之前，长下摆要盖住靴口
arms        手臂（皮肤）
propBack    背在身后的武器（长枪斜跨 → 外套遮住中段，这才叫"背着"）
clothes     衣服本体（外套/裙摆/袖子/领子/围巾/腰带/护肩）
propMid     握在手里的武器 ← 在手的下面，所以手指是"握"上去的
hands       手
gloves      手套袖口
head        头（耳朵 → 脸 → 单侧阴影，阴影用 clipPath 裁回脸型）
face        五官
hairFront   刘海与鬓发
hairAcc     发饰（护目镜、雪花簪、头环）
propFront   浮空物与光效（法球、雷弧）
motif       元素氛围
```

`test/art.js` 断言这个顺序列表本身，以及每一层的几何边界。

## 五、表情是参数，不是四张画

```js
neutral: { open: 1,    browTilt: 0,     browRaise: 0,  mouth: 'line', mouthCurve: 0.2 }
focus:   { open: 0.74, browTilt: -0.22, browRaise: -2, mouth: 'line', mouthCurve: -0.15 }
hurt:    { open: 0.5,  browTilt: -0.55, browRaise: -4, mouth: 'open', mouthCurve: -0.6 }
victory: { open: 0.12, browTilt: 0.24,  browRaise: 5,  mouth: 'open', mouthCurve: 1 }
```

四个数字改眼型、眉角、眉高、嘴形，几何是共享的。
所以"笑的脸"不可能和"平静的脸"错位——那是手绘表情表最容易出的问题。

眼睛的虹膜**故意画得比眼眶大**，用 `clipPath` 裁掉：
正好塞进眼眶的虹膜看起来永远像一颗浮着的圆盘，被上下眼睑切掉才像眼睛。
`test/art.js` 会断言四种表情渲染结果互不相同。

## 六、敌人：四块积木

非人形，但共享配色、线宽、光照方向和元素氛围。画布 `0 0 400 400`，地面 y = 348。

| 积木 | 用途 |
|---|---|
| `blob` | 圆滑的团块——虫身 |
| `plate` | 硬边多边形——甲壳、石头、装甲 |
| `spike` | 尖锥——口器、爪、角、腿 |
| `eye` | `round` / `slit` / `cluster` 三种眼型 |

灰烬之王有两个 `build`。二阶段不是换色：外壳裂开、核心露出来、王冠变高。
`test/art.js` 断言二阶段至少多出 4 个形状。

## 七、怎么加一个新角色的美术

见 [`TEMPLATE.md`](TEMPLATE.md#加一个新角色的立绘)。最短路径：

1. 在 `src/core/characters.js` 里 `defineCharacter`（数据）。
2. 在 `src/art/specs/characters.js` 的 `ART` 里加一条（画什么）。
3. `node test/art.js` 应该报错说缺 spec——修好它。
4. `node tools/art-sheet.js` 看对照图。

## 八、怎么检查美术（因为作者看不见）

这套美术是在**没有图像输入能力**的条件下写的。几何可以推理，
但"这到底是不是一个人"推理不出来。所以有两层替代手段：

### `test/art.js` — 纯 Node，21 项

不需要浏览器。检查覆盖完整性、SVG 合法性、id 唯一性、
**几何是否超出画布**（用控制点做保守上界：三次贝塞尔一定落在控制点的凸包里，
所以坐标都在画布内 ⇒ 曲线一定也在）、bust 裁切是否框住头、
姿势/身高是否重复、四种表情是否真的不同、Boss 二阶段是否只是换色。

### `tools/art-sheet.js` — 无头浏览器，读像素

```
node tools/art-sheet.js
```

会生成 `docs/art-sheet.png`（给人看的对照表），并且把每张图栅格化后读回像素，
打印可以自动判断的数字：

| 指标 | 抓什么 |
|---|---|
| `fill` | 覆盖率。接近 0 = 图形跑到画布外或缩没了；接近 1 = 某个形状失控了 |
| `bbox` | 墨迹实际落在哪。贴边 = 被裁切，这是最常见的生成器 bug |
| `head/top` | 顶部 15% 最宽处 ÷ 全图最宽处。接近 100% = 头过大或图倒了 |
| 五官取样 | 在 bust 上取固定点：头顶必须是头发、双眼必须够暗、脸颊必须是暖肤色 |
| 剪影重合度 | 同类形象两两的 IoU。> 93% = 两张画其实是一样的 |

五官取样是这里最值钱的一项：包围盒可以完美，而刘海已经长到眼睛上了。
"这里应该有一张能看的脸"只能靠采样那几个像素来断言。

## 九、踩过的坑

| 问题 | 症状 | 根因 |
|---|---|---|
| **缓存键漏了 `plain`** | 剪影测量全部带上背景光晕，覆盖率全是错的 | `renderArt` 的 key 少了一个会改变输出的选项，第一次非 plain 渲染污染了缓存 |
| **`<line>` 坐标提取把属性名当数字** | 每个形象都像挂在画布左边（x = 1） | 正则匹配属性串里的所有数字，把 `x1` 里的 `1` 也算了进去 |
| **缩放锚在地面，头发却按绝对高度长** | 白鸦（1.03）和军需官（1.04）的头发被画布顶部裁掉 | 顶部余量随身高线性减少，改发型时不会想到这一层 |
| **NPC 借用角色头像** | 旅店老板娘长得和艾莉丝一模一样 | `world-data.js` 里 `portrait: 'elise'`，而美术是按 id 查的 |
| **头发和皮肤同色** | 艾莉丝（`#e8c98a` vs 肤色 `#ecc3a4`，RGB 距离 27）的刘海和额头糊成一块 | 五官取样里的"色差 ≥ 45"这一项抓到的 |
| **圣杖戳出画布** | 艾莉丝 bbox 右边 = 1.00 | `reach` 姿势把手腕推到 x = 386，杖头再往右 58 |
| **同一批测试里的两个真 bug** | 剪影 IoU 90%+ | 五个角色共用骨架 → 必须靠姿势、身高、服装宽度拉开差距 |

## 十、已知的取舍

- **单张立绘约 32 KB（平均），最大 49 KB。** gzip 后约 16 KB。
  再小就要牺牲曲线精度或减少图层，目前不值得。
- **头像没有裁掉下半身。** `view=bust` 只换 viewBox，图层的几何还是全身。
  好处是服务端只有一份几何；代价是头像文件比理论值大。
  真要优化就在 `figure()` 里按 y 过滤图层，但收益不值这个复杂度。
- **敌人头像和全身一样大。** 敌人不需要头像，`bust` 只是给 UI 留的余地。
- **没有待机动画。** 眨眼需要把 SVG 内联进 DOM（`<img>` 里的动画不受外部 CSS 控制），
  而内联会让同一张图在页面里出现四份。目前判断不值。
